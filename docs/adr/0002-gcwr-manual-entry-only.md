# GCWR: manual entry only for v1, manufacturer lookups deferred

GCWR isn't printed on any physical tag. Unlike Axle Count, we do know of a plausible automated source: Ford publishes a public towing calculator that returns GCWR by VIN, and the VIN is already on the certification label we're photographing. We're deferring that lookup to the backlog and requiring manual GCWR entry for every Truck Profile in v1, regardless of manufacturer. The Ford tool is a public webpage, not a documented API — automating it would likely need headless-browser scraping, can break silently whenever Ford changes the page, and its terms of use may restrict automated querying. That's a materially different risk profile than the Claude-vision OCR the rest of the app is built around, and there may be other manufacturers with similar tools worth surveying before committing to an integration shape.

**Consequences**: GCWR entry is manual for every Truck Profile in v1, even for Ford vehicles where a lookup path is known to exist — and it's optional, not required: a user who can't find or doesn't know their GCWR can complete profile setup without it. Any weigh event run against such a profile simply skips GCWR Overload, reporting it as "not evaluated — no GCWR on file" rather than blocking Axle Overload or Hitched GVWR Overload. Because a manually-entered GCWR can't be verified against any document, results are also labeled as an Unverified Value wherever they depend on one, distinct from checks backed by an OCR'd tag or Ticket. Revisit the lookup gap once the actual-weight-based core is proven, as a scoped follow-up that surveys available manufacturer sources (Ford and others) before building.
